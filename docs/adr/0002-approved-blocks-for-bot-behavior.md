# Assemble bot behavior from approved blocks

Piko will represent bot behavior as flows assembled from developer-implemented, approved blocks rather than executing code generated by the builder agent. This limits what the future agent can make a bot do while supporting reusable templates; introducing a new capability requires implementing a block. Initial bots focus on buttons and data collection, with AI replies a possible later block, and the builder agent itself is outside this milestone.

Templates construct flows for one shared runtime rather than each having their own execution logic. A bot can combine several configured forms behind a menu, and owners initially configure menus and question blocks through ordinary settings rather than a visual block editor.

The Bot studio adds an interactive Flow canvas for inspecting approved Blocks and requesting changes to them through Piko. It represents the supported Flow faithfully and does not offer direct graph editing; changes continue through the Builder agent or manual settings. This keeps the canvas aligned with the approved-block boundary while making the Bot's behavior easier for its owner to understand.
